# 工程逻辑架构

> 面向"多任务深度学习 + 建筑物矢量化"的可视化原型。约 3200 行 Python，
> 分为 **表现层（app/）**、**算法层（src/）**、**任务层（scripts/）** 三层，
> 依赖方向单向：`scripts/app → src`，`src` 不反向依赖界面。

## 1. 分层视图

```
┌─────────────────────────────────────────────────────────────────────┐
│ 表现层 / 交互层                      app/                            │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  ┌──────────┐ │
│  │  gui.py      │→ │ viewer.py    │  │ compare.py   │  │sysinfo.py│ │
│  │  主窗口/调度  │  │ 画布/顶点编辑 │  │ 批量对比窗口  │  │资源探针   │ │
│  └──────┬───────┘  └──────────────┘  └──────┬───────┘  └──────────┘ │
│         │                                   │                       │
├─────────┼───────────────────────────────────┼───────────────────────┤
│ 算法层 / 领域层                      src/                            │
│         ▼                                   ▼                       │

│  │ 载入/滑窗推理 │→ │ 掩膜→矢量     │→ │ 矢量指标      │               │
│  └──────┬───────┘  └──────┬───────┘  └──────┬───────┘               │

│  └──────────────┘  └──────────────┘                                 │
├─────────────────────────────────────────────────────────────────────┤
│ 任务层 / 入口                        scripts/ + run_vectorizer.py    │
│  train.py  evaluate.py  ablation_benchmark.py  selfcheck_*.py ...     │
└─────────────────────────────────────────────────────────────────────┘
```

依赖是**有向无环图**（实测 import 边）：

```
run_vectorizer.py ──► app.gui
app.gui ──► app.compare, app.viewer, app.sysinfo
        └─► src.infer, src.vectorize, src.vector_metrics, src.esri_shapefile
app.compare ──► src.vectorize, src.vector_metrics
src.infer ──► src.models, src.dataset
src.vector_metrics ──► src.vectorize, src.metrics
scripts/* ──► src.*（ablation_benchmark 额外复用 app.compare 的批处理函数）
```

`src/` 里没有任何 `import app`，因此算法层可脱离界面单独测试——这也是
`scripts/selfcheck_vectorize.py` 能在无显示环境下验证全流程的原因。

## 3. 核心数据契约

整条链只传四种东西，类型稳定，方便替换其中任一环：

```python
image:  np.ndarray  # (H, W, 3) uint8, RGB
prob:   np.ndarray  # (H, W) float32, [0,1] 建筑概率
edge:   np.ndarray | None  # (H, W) float32, 边界概率（仅 full 模型）

VectorConfig:  # 算法的全部开关与参数（dataclass，不可变使用）
  threshold=0.50, use_boundary=True, use_vertex=True, use_geometry=True,
  edge_threshold=0.45, edge_quantile=0.90, use_edge_cut=True,
  min_area=40, simplify_ratio=0.012, rect_tolerance_deg=14,
  rect_min_support=0.55, split_peak_size=11, split_min_peak=1.8,
  split_min_part=0.22, split_max_parts=4, split_size_factor=2.0

VectorResult:
  polygons: list[BuildingPolygon]   # points(N,2) float32 + area/perimeter/score/regularized
  mask: (H,W) uint8
  instances, merged_blobs, regularized: int
  timings: dict[str, float]         # threshold/separation/contour/vertex/geometry
  config: VectorConfig

metrics: dict[str, float]  # mIoU, boundary_iou, polygon_iou, chamfer_matched,
                           # polis, f1, rectilinearity, merge_rate,
                           # instance_recall, instance_precision, ...
```

## 4. 运行时序

### 4.1 单图推理（F5）

```
用户点"运行推理"
  └─ gui._on_run()
       ├─ cfg = gui._config()                 # Tk 变量 → VectorConfig 快照
       ├─ 禁用按钮，状态栏改文案
       └─ threading.Thread(work)
            ├─ engine.predict_timed(image, model, want_edge)
            │     ├─ 反射填充到 tile 整数倍
            │     ├─ 按 0.5·tile 步长切块，batch 前向
            │     ├─ sigmoid → 概率，按斜坡权重加权融合
            │     └─ 裁回原尺寸
            ├─ vectorize(prob, edge, cfg)     # 见 4.4
            └─ queue.put(("run", payload))
  ← gui._poll_queue()（每 60ms，主线程）
       └─ _apply_run(payload)
            ├─ view.set_overlays(mask, boundary, gt)
            ├─ view.set_polygons(result.polygons)
            ├─ _refresh_metrics()             # evaluate_vectors
            ├─ _show_timing()                 # 各阶段耗时
            └─ 恢复按钮
```

**线程规则**：Tk 控件只在主线程碰；工作线程只做 numpy/torch 计算并通过
`queue.Queue` 回传；主线程用 `after()` 轮询消费。对比窗口用同一套模式。

### 4.2 顶点编辑

```
拖拽顶点（viewer._on_left_drag）
  └─ 直接改 BuildingPolygon.points[j]（numpy 原地写）
       └─ _draw_polygons()                # 只重画矢量层，不重采样底图
松开鼠标 → on_vertices_changed 回调
  └─ gui._on_vertices_changed()
       ├─ result.polygons = polygons      # 让导出使用编辑后的几何
       └─ _refresh_metrics(polygons)      # 重新算多边形 IoU/Chamfer
```

"重置矢量"走另一条路：复用缓存的 `_prob/_edge`，只重跑 `vectorize()`，
不重新推理，所以是毫秒级。

### 4.3 批量对比

```
CompareWindow._start()
  └─ 抽样 N 张测试图块 + 当前 VectorConfig 作为基线
       └─ run_batch(engine, job)
            for 每个模型:
                for 每张图: engine.predict → 缓存 prob/edge   # 推理只做一遍
                for 每组配置: vectorize(缓存 prob, cfg) → evaluate_vectors
            → rows[{config, model, mIoU, polyIoU, chamfer, ...}]
       └─ 主线程填 Treeview + 画柱状图 + 给"最优方案"结论
```

`run_batch` 的模型×图块结果缓存是关键：4 组配置共享同一次推理，所以
"4 配置 × 3 模型 × 16 图"只需 48 次前向。

### 4.4 矢量化内部流水线（`vectorize`）

```
prob ──阈值──► mask ──形态学开──► blobs（按连通域 + bbox 裁剪）
                                  │
edge ──分位数阈值 + 膨胀──► cut ───┤
                                  ▼
                    _separate_instances: 只对"显著大于中位面积"的 blob
                      ├─ 有 cut：用 cut 切开后的连通块作种子
                      ├─ 无种子：距离变换局部极大值作种子
                      └─ 最近种子划分（无缝隙，不缩面积）
                                  │
                       每个实例 → _dense_contour（CHAIN_APPROX_NONE）
                                  │
                 _contour_to_polygon：DP 选角点 → 分段直线拟合 → 交点求顶点
                                  │
                 regularize_polygon：主方向估计 → 0/90° 吸附 → 自交/面积校验
                                  │
                         BuildingPolygon（面积/周长/置信度/是否规则化）
```

## 5. 状态与所有权

| 状态 | 存放位置 | 说明 |
|---|---|---|
| 算法配置 | Tk `*_var` | 界面上是唯一真值源；`_config()` 每次运行生成快照，运行期间不受界面改动影响 |
| 当前影像/真值 | `gui.current` dict | `image`、`gt`、`name`、`label` |
| 最近一次结果 | `gui.result`（`VectorResult`） | 导出、重置、指标刷新都读它 |
| 可编辑多边形 | `viewer.polygons` | 与 `result.polygons` 同一批对象；编辑即改对象 |
| 概率缓存 | `gui._prob/_edge` | 供"重置矢量"与切配置复用，避免重复推理 |
| 模型 | `InferenceEngine._cache` | 进程内按名字缓存，切换模型不重复加载 |

## 6. 扩展点

| 想替换的东西 | 改动位置 | 影响面 |
|---|---|---|
| 换分割网络/主干 | `src/models.py::build_model`，保持 `forward(x, return_edge)` 契约 | 训练脚本 + 推理引擎自动适配 |
| 换顶点回归（真正的 GCN） | `src/vectorize.py::_contour_to_polygon` 内部调用模型 | GUI/指标/导出不变 |
| 换实例分离策略 | `src/vectorize.py::_separate_instances` | 同上 |
| 加评价指标 | `src/vector_metrics.py::evaluate_vectors` 返回值 + `app/compare.py::METRIC_COLUMNS` | 表格与图表自动多一列 |
| 加导出格式 | 仿 `write_geojson` / `write_polygon_shapefile`，在 `gui.py` 导出菜单挂一项 | 局部 |
| 接 GeoTIFF 地理坐标 | `src/esri_shapefile.py` 写 `.prj`，`write_geojson` 换 CRS | 导出层 |

## 7. 设计取舍与已知问题

1. **`app/compare.py` 一个文件里混了"批处理逻辑"与"Tk 窗口"**。`run_batch`
   是纯函数、无 UI 依赖，被 CLI 直接复用；若后续继续长大，建议拆成
   `app/batch.py`（纯计算）+ `app/compare_window.py`（界面）。
2. **`app/gui.py` 753 行偏大**，承担了布局、状态、线程、导出四件事。可进一步
   拆出 `gui_export.py` 与 `gui_sections.py`，但当前规模尚可维护。
3. **顶点回归是确定性几何算法，不是学习模块**。接口（`use_vertex`）已按学习
   版本设计，替换时不影响上层。
4. **推理线程无进度回调**，1500×1500 影像只有"推理中…"文案；若要细粒度进度，
   需给 `InferenceEngine.predict` 增加 `progress_cb`。
5. **无 GPU 抽象**：`InferenceEngine` 固定 CPU（`map_location="cpu"`），换 GPU
   需在 `load()` 与 `predict()` 里加 device 管理。
6. **`src/metrics.py` 与 `src/vector_metrics.py` 并存**：前者是早期像素级评测
   复用，后者是矢量级评测；两者都保留是为了与 `scripts/evaluate.py` 的历史结果
   对齐，合并会破坏已有指标的可比性。
