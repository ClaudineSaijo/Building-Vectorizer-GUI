# 多日训练与测试计划（06:30–13:50 / 16:00–23:00 双窗口）

> 前提：每天可运行时段为 **06:30–13:50 与 16:00–23:00**（其余时间停机或空闲）；训练不压缩规模。
> 机制：`scripts/day_runner.py` + `runs/dayplan/tasks.json`，窗口内自动挑任务，
> 22:10 干净停止，次日用 `--resume` 续跑（最多损失 1 个 epoch）。

## 1. 运行方式

每天早上开机后，双击项目根目录的 **`start_day_runner.bat`** 即可。
队列会按 `tasks.json` 顺序执行，进度写在：

- `runs/dayplan/day.log`（每任务起止、状态）
- `runs/dayplan/state.json`（当前任务、历史）
- `runs/dayplan/<任务名>.log`（每个任务的完整输出）

规则：

| 规则 | 说明 |
|---|---|
| 窗口 | 06:30–13:50 与 16:00–23:00；每个窗口结束前 5 分钟终止当前任务并保存到最近 epoch |
| 续跑 | 所有训练都带 `--resume`，次日同一条命令继续 |
| 缺依赖 | `needs` 里的文件不存在 → 每 20 分钟重试，3 次后跳过 |
| 热更新 | 队列每轮重读 `tasks.json`，可随时增删任务 |

## 4. 每天早上的检查清单（我负责）

1. 看 `runs/overnight/status.json` 或 `runs/dayplan/state.json`；
2. 确认前一晚的 `best.pt` 是否更新、val IoU 曲线是否正常；
3. 把新出的权重接入评估，更新 `docs/矢量评价协议.md`；
4. 如某任务连续失败，改参数后放进队列；
5. 汇报当天计划与昨日结果。

## 5. 风险与应对

| 风险 | 应对 |
|---|---|
| 22:10 终止时正在跑 epoch | 最多损失 1 个 epoch（512 约 71 min），`--resume` 次日继续 |
| 断电/关机 | `state.json` 记录进度，次日重跑 bat 即可 |
| WHU-Mix 解压后标注偏移 | 先抽检 20 张，偏移大就只用人工修正子集 |
| GCN 不达标 | 降级为消融，主线回到多任务+几何+评价 |
| 磁盘不足 | 每个 zip 解压后立即删除；G 盘约 395 GB 可用 |
